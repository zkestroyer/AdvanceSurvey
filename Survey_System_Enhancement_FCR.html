Survey System Enhancement Requirements

Functional Change Request (FCR)

Project: Survey Application
Prepared For: Development Team
Date: 23 July 2026

1. Brand-wise Product Mapping

Objective

Display only the products belonging to the selected brand instead of displaying all products.

Existing Behavior

  • All products are currently displayed together regardless of the selected Brand.

Required Changes

Web Portal

A Product Mapping module shall be implemented within the Survey Configuration.

  • Configure Product Categories.
  • Configure Brands.
  • Configure Products.
  • Map one or more Products against a Brand.
  • Update or remove mappings at any time.

The mapping shall be maintained according to the Product Catalog configured in the Web Portal.

Mobile Application

  • Display Brand after Product Category selection.
  • Display only mapped products after Brand selection.
  • Unmapped products shall not be displayed.

2. Dynamic "Other" Option Handling

Objective

Provide a configurable mechanism for handling the "Other" option across all dropdown fields.

Existing Behavior

Currently, selecting "Other" does not allow users to specify a custom value.

Required Changes

Whenever an administrator configures a dropdown LOV containing the value "Other", the application shall automatically treat it as a special value.

Mobile Application Behavior

  • Selecting Other shall automatically display a text field below the dropdown.
  • The entered value shall be saved with the survey.
Technical Note:
  • No additional configuration shall be required.
  • The application shall automatically detect the value "Other".
  • This behavior shall work for every configurable dropdown.

3. Multiple Product Entry

Objective

Allow multiple products to be captured within a single survey.

Existing Behavior

Only one product can currently be added for each Product Category.

Required Changes

  • Users can tap Add Another Product after completing a product.
  • The same form shall open again.
  • Multiple products shall be stored under the same survey as child records.

Example Flow

Survey → Solar Product 1 → Add Another Product → Solar Product 2 → Add Another Product → Solar Product 3 → Continue Survey

6. Management Portal & Mobile Application

The existing Survey Mobile Application shall be reused. No separate mobile application shall be developed.

A new Management role shall be introduced. The same functionality shall be available on both the Web Portal and the Mobile Application.

Dashboard

  • KPI Cards
  • Interactive Charts
  • Graphs
  • Territory-wise Performance
  • Brand-wise Statistics
  • Product-wise Statistics
  • Survey Trends
  • Distributor Analysis

Reports

Basic Reports

  • Shop Reports
  • Survey Reports
  • Territory Reports
  • User Reports

Advanced Reports

  • Comparison Reports
  • Product Comparison
  • Price Comparison
  • Price History
  • Trend Analysis
  • Product Analysis
  • Brand Analysis
  • Distributor Analysis
  • Territory Analysis

Comparison Engine

Management users shall be able to perform the same dynamic comparisons described in Section 5 from both the Web Portal and the Mobile Application.

  • Compare Products
  • Compare Brands
  • Compare Distributors
  • Compare Purchase Prices
  • Compare Selling Prices
  • Compare Territories
  • Compare Cities
  • Compare Product Categories
  • Compare any configurable survey field

The comparison results shall support Highest/Lowest sorting, Graphical View, Tabular View, Drill-down into survey records, Historical Pricing Timeline, Historical Price Comparison and Shop Count.
