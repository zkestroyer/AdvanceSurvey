# Fix Mobile App Survey Forms 

## Issue Analysis
The reason the new forms are not showing up in the app is because the survey schema is strictly controlled by your **backend server**. The previous attempt tried to force the Flutter app to change fields (like changing "Capacity" to a dropdown) on the fly, but it failed because **some of the requested fields didn't even exist in the server's survey data**.

Also, the logic added to filter Models based on Brand was completely broken—it searched the entire survey for "Brand" instead of looking at the specific section you were in, causing it to grab the wrong brand entirely.

## Proposed Changes

### 1. Update the Backend Database (Source of Truth)
Instead of hacking the mobile app, we must fix the root cause. I will write a script (`backend/seed_survey.ts`) to inject a **brand new Survey Template** into the database that perfectly matches your Excel sheet. 
- It will include all missing fields: Technology, Power (Watts), Power (KW), Capacity, Voltage, Energy, IP Rating, Logistics, Category, etc.
- All dropdowns will have their correct options natively stored in the database.
- It will be set as the new `isActive: true` template.

### 2. Clean Up Mobile App (`survey_execution_screen.dart`)
- **Remove the hacky overrides**: I will delete the ~90 lines of code that tried to forcibly change field types on the fly. The app will now trust the server.
- **Fix Brand/Model filtering**: I will update the logic so that when you select a Brand in "Lithium Batteries", it only filters the Model dropdown *within* "Lithium Batteries", instead of accidentally grabbing the Brand from "Solar Panels".
- **Ensure Numpad works**: Now that the server will send the correct types (e.g., `number` for Contact No), the Numpad will naturally trigger.

## Verification Plan
1. Run the database seed script to push the new survey template to your local database.
2. Compile a fresh APK.
