Phase 3B: API Contract & Payload Specifications

CRITICAL RULE: This contract dictates exactly how the frontend and backend communicate. Changes to these payloads must be updated here immediately so the AI and frontend developers don't break the application.

1. Global API Standards

  • Base URL: /api/v1
  • Content-Type: application/json
  • Authentication: Bearer Token (JWT) in Authorization header.

2. Standard Response Wrapper

All successful API responses must follow this exact structure:

{
  "success": true,
  "message": "Human readable message here",
  "data": { ... },
  "errors": null
}

3. Endpoints Documentation

3.1. [Module Name: User Auth]

Endpoint: POST /auth/login

  • Description: Authenticates user and returns JWT.
  • Request Payload: json { "email": "user@example.com", "password": "securepassword123" }
  • Success Response (200 OK): json { "success": true, "message": "Login successful", "data": { "token": "eyJhbG...", "user_id": "123-abc", "role": "admin" }, "errors": null }
  • Error Response (401 Unauthorized): json { "success": false, "message": "Invalid email or password", "data": null, "errors": ["credentials_mismatch"] }
