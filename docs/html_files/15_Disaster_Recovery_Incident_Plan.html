Disaster Recovery (DR) & Incident Response Plan

1. Incident Response Roles

  • Incident Commander: (Who takes charge during an outage)
  • Communications Lead: (Who updates the client/users)
  • Technical Lead: (Who fixes the issue)

2. Incident Classification Matrix

  • Tier 1 (Critical): Complete system outage, data breach. (Response SLA: 15 mins)
  • Tier 2 (High): Core functionality broken (e.g., checkout failed). (Response SLA: 1 hour)
  • Tier 3 (Medium/Low): Minor bugs, cosmetic issues. (Response SLA: 24 hours)

3. Disaster Recovery Procedures

Scenario A: Database Corruption / Loss

  1. Identify the exact time of corruption.
  2. Stop all write operations to the database.
  3. Retrieve the latest automated snapshot from AWS/Cloud provider.
  4. Restore to a staging environment and verify integrity.
  5. Swap production database connection to the restored instance.

Scenario B: Server/Infrastructure Failure

  1. Auto-scaling triggers should handle minor node failures.
  2. If region-wide outage, initiate failover to the secondary region.
  3. Update DNS routing (Route53/Cloudflare) to point to the secondary region.

Scenario C: Security Breach / Ransomware

  1. Immediately isolate the affected servers (cut external access).
  2. Identify the compromised entry point.
  3. Patch the vulnerability.
  4. Restore clean infrastructure from Infrastructure-as-Code (Terraform/Ansible) templates.
  5. Notify clients and authorities as per legal compliance.
